# Popo v0.17.1

Version 0.17.1 generalizes contributor hooks for reuse and strengthens repository hygiene. This
patch release is dated 2026-11-06 and documented in released form at the maintainer's request.
Tagging and publication remain separate operations.

## Highlights

Run `make check-pre-commit` for Popo's repository-policy gate. Common hook interfaces and Python
file selection now support future shared-hook packaging without importing another consumer's native,
security or branch policy. See the [contributor guide] and [changelog] for scope and usage.

## Change Scope

Rename the repository hook to `make-check-pre-commit`, retaining `popo-self-check` as a runnable
alias. Its generic Make entry point delegates to the existing `self-check`; the pre-push gate still
runs the full local quality gate. Separate shared Python tooling from repository-specific gates.

Select nested `tests/` and `Tests/` Python trees without hard-coding test-layer names, excluding
shared `support/` directories and `fixtures.py`. Share managed Ruff dependency constraints through
one YAML anchor. Move autopep8's line-length setting into canonical tool configuration, preserving
its 88-character limit, ignored codes and Ruff-compatible formatting.

Enable JSON syntax/duplicate-key checks and conflict-marker detection outside active merges.
Preserve hook revisions, existing security checks, protected branches, compatibility formatting,
manual typing, dependency constraints and execution stages. Document eventual shared hook manifests
while retaining consumer-specific configuration. No new shared repository is created.

## Compatibility and Configuration

This patch changes contributor automation and documentation, not installed Popo commands or consumer
policy schemas. Runtime requirements, native-check reporting and exit behavior remain unchanged.
Existing `make self-check` and manual `popo-self-check` hook invocations remain supported. Versions
continue to derive from Git tags through `setuptools-scm`; no release-version constant is added.

### Breaking Changes

No intentional runtime, CLI or consumer-configuration removal is introduced. Local hooks now reject
invalid or duplicate-key JSON and leftover conflict markers even outside active merges. Naming
checks also apply to nested test trees. Correct those files rather than disabling the checks.

### Deprecations

No new deprecation or support-window commitment is introduced. The former hook identifier is
retained as an alias; no removal date is established.

## Support Boundary

Popo requires Python >=3.13,<3.15. Native checks remain offline and read-only. Pre-commit setup may
download managed environments, and existing formatter hooks can rewrite files. The new hygiene
checks do not rewrite their inputs. Contributor tooling remains separate from native consumer
checks.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.
Validate fresh wheel and source distributions, Twine metadata and clean installations. Development
SCM versions do not establish metadata produced by the eventual immutable v0.17.1 tag.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. This preparation creates no tag or hosted release and publishes no package. No data
migration is required. Adopt the reviewed pin and matching contributor configuration; roll back by
restoring the prior verified pin and configuration. Hosted enforcement is a separate concern.

## Known Limitations and Follow-Up

Shared hook definitions can later live in a versioned repository's `.pre-commit-hooks.yaml`.
Consumers still select revisions and retain explicit project policy; identical whole-file configs
are not required for useful reuse. Taiscora's Swift, asset, secret-baseline and branch-history rules
remain purposeful differences and were not copied into Popo.

Rebuild and validate the final committed/tagged tree, intended version and release record before
delivery. Local validation does not establish hosted Linux/Windows or Python 3.13 success.
