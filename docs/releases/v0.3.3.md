# Popo v0.3.3

Version 0.3.3, tagged on 2026-09-30, reorganizes unit tests to align with Popo's checker and
configuration subpackages. This patch candidate covers the complete `feature/reorganize-unit-tests`
branch merged into `develop` since `v0.3.2`, including the shared-helper import correction and
related documentation. The intended tag is `v0.3.3`; it has not been created. See the [changelog].

## Highlights

- Group checker tests under `tests/unit/checks/` and configuration tests under
  `tests/unit/configs/`.
- Separate automation configuration validation from checker scenarios and correct its shared-helper
  import.
- Preserve all 274 default test cases, shared fixtures, unit markers, and default discovery.
- Update test-selection guidance and source-to-test references.

## Change Scope

Six checker test modules move into `checks/`, matching the modules in `popo.checks`. Project-loading
and shared configuration contracts move into `configs/test_project.py`; automation configuration
validation moves into `configs/test_automation.py`. Both directories have package initializers.
Support, Makefile, hook, and repository-workflow tests remain directly under `tests/unit/`.

The automation configuration test imports `FileWriter` from `tests.support.files`, correcting a
relative import that incorrectly resolved beneath `tests.unit.configs`. Module descriptions,
`tests/README.md`, the root README, the change-impact map, and the changelog reflect the new layout.
The [test layout] documents focused selection through the existing Make interface.

Package implementation, dependency requirements, pytest configuration, and workflow behavior are
unchanged. The reorganization preserves the existing test scenarios and assertions.

## Compatibility and Configuration

No consumer compatibility or configuration changes. CLI commands, flags, settings, diagnostics,
output, and exit codes retain their behavior.

Contributors invoking test files directly must use their new paths. `make test`, `make test-unit`,
and `make check` retain their existing discovery scope. Shared fixtures remain in `tests/support/`.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`, with runtime dependencies
`packaging>=26.3,<27` and `PyYAML>=6.0.3,<7`. Internal checker modules remain outside the promised
consumer API.

## Validation

Local validation on 2026-09-30 passed against the 0.3.3 working-tree candidate:

- `make release-changelog RELEASE_VERSION=v0.3.3` found the matching dated entry.
- `make docs-markdown` passed local link and heading-anchor validation.
- `make check-release` with a fresh temporary `PYTHON_DIST_DIR` passed lint, formatting, strict
  typing, all 274 unit/integration tests, repository checks, wheel/source builds, `twine check`,
  and all 18 artifact/clean-install tests.
- `git diff --check` passed. Release-document reference definitions are sorted and unique, and
  earlier dated changelog entries are preserved.

The release gate downloaded isolated build and installation dependencies. Its distributions have a
Git-derived development version, not final `0.3.3`; passing these checks does not establish eventual
tag/version agreement, hosted cross-platform success, or publication. This validation-results
wording was added after the artifact run and rechecked with the Markdown and changelog gates.

## Deployment and Rollback

No cloud deployment, data migration, or PyPI publication is introduced. Authorized tagging triggers
release validation; GitHub publication retains its separate manual opt-in and environment safeguards
in the [release policy]. No tag or publication is established by this record.

A rollback of the test layout must restore matching imports and documentation paths together. It has
no runtime or consumer-data effect. Correct released defects through a subsequent version and
preserve existing tag identities.
