# Popo v0.3.0

Version 0.3.0, tagged on 2026-09-30 (UTC), adds configurable automation-contract validation and
reorganizes configuration by policy domain. This minor release covers all changes from
`feature/add-automation-contract-validation` merged into `develop` since `v0.2.4`, including tests
and documentation repairs. The tag does not establish hosted validation or publication. See the
[changelog].

## Change Scope

The checker adds static validation without executing automation or fetching remote code. Discovery
supports workflow, action, template, and generic YAML globs. Configured repository aliases resolve
to local targets; placeholder exemptions are limited to self-targeting templates.

The `popo.config` subpackage replaces the previous configuration module with shared TOML helpers,
project orchestration, and separate dependency, Python-policy, and automation modules. Shared helper
names distinguish cross-module utilities from module-local functions; explicit package exports
preserve the established configuration imports.

Tests cover checker failures, configuration boundaries and defaults, CLI dispatch, wheel/source
contents, and installed commands. Documentation updates cover settings, source paths, changelog
version links, release-index wording, and the PR badge's branch filter.

Unrelated, uncommitted root-documentation additions are not part of this release scope.

## Compatibility and Configuration

Existing commands and their options remain available. The new command is additive and returns the
usual reported-check statuses: `0` for success and `1` for findings or configuration failures.
Invalid arguments remain argparse errors with exit status `2`.

The standalone automation command uses default workflow discovery without a configuration table.
Adding `[tool.popo.automation]`, even an empty table, enables automation validation in `check-all`
and may expose new failures in a previously passing consumer repository. Test the standalone command
before enabling aggregate checking.

All automation settings are arrays of nonempty strings; unknown keys are rejected. Existing
dependency and Python-policy defaults and unknown-key handling remain unchanged. See the
[configuration reference] and [automation guide] for discovery settings, aliases, path boundaries,
and examples. `--pins-only` skips input, composite, and metadata checks while retaining YAML parsing
and local-target resolution.

No migration is required for existing `popo.config` imports. Internal checker modules remain outside
the promised consumer API; adoption examples use the public CLI.

## Support Boundary

Python remains `>=3.13,<3.15` and `packaging>=26.3,<27` remains required. This release adds
`PyYAML>=6.0.3,<7` at runtime, its matching minimum constraint, and development typing stubs.
Refresh the installed environment so the new parser dependency is available.

Checks remain read-only and credential-free. They do not verify remote commit existence, container
immutability, arbitrary expressions, or the full GitHub workflow schema. Local aliases describe the
current checkout, not a historical or remote revision. Retain actionlint and hosted tests.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations].

To stop newly enabled aggregate automation checks, remove the consumer's automation table after
reviewing its policy needs. To restore the prior package, pin the previous reviewed release and
remove invocations of the new command from consumer tooling. Preserve independent checks that still
enforce the intended policy. Correct published defects through a new version rather than replacing
release artifacts.
