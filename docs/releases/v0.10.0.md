# Popo v0.10.0

Version 0.10.0 adds explicit committed-source inventory generation in plain JSON and source-only
SPDX 2.3. This minor release record is prepared in released form for 2026-10-25; tagging and
publication are separate operations and have not been performed for this candidate.

## Highlights

See the [changelog] for concise changes and the [source inventory guide] for invocation, formats,
limits and consumer adoption. The new command generates evidence without changing consumer files
or running package manifests.

## Change Scope

Add `popo source-inventory --revision REVISION`, with optional `--root`, `--name` and
`--format json|spdx`. Resolve the selected revision once to a commit, enumerate its full tree and
batch-read committed blobs by object ID. Share revision identity, file collection and checksum
logic across both renderers. Ignore index and checkout edits, disable replacement objects and
clear inherited Git repository-selection overrides. Preserve symlink link-text semantics and Git
modes; reject gitlinks/submodules rather than claiming their contents were scanned.

Emit schema-version-one JSON with sorted paths, Git modes, SHA-256 hashes and the resolved commit.
Emit source-only SPDX 2.3 with path-derived file identifiers, SHA-1/SHA-256 hashes, source-package
relationships and a package verification code. Use NOASSERTION for source license and copyright
claims; SPDX's CC0 data-license field does not license consumer source. Plain JSON is reproducible
for identical names and commits; SPDX namespaces and creation timestamps vary by generation.

Add isolated committed-repository fixtures and unit/CLI scenarios for revisions, checkout edits,
Git environment overrides, symlinks, unsupported tree entries and malformed Git responses. Exercise
both formats through installed console-script and module entry points for wheels and sdists.
Document command selection and adoption in the README, configuration guide and dedicated guide.

## Compatibility and Configuration

This is a new optional capability, so it advances the minor version. Existing checker commands,
profiles, native check-result JSON, dependencies and package-root exports retain their contracts.
`source-inventory` has no policy table and is excluded from `check-all` and profiles; consumers must
invoke it explicitly with a revision. CLI helper reordering preserves existing dispatch behavior.

Successful generation returns zero with one JSON evidence document on stdout. Collection/rendering
errors return one with a diagnostic on stderr and no partial evidence on stdout; argument errors
retain status two. Shell redirection belongs to the caller and may create an empty output file on
failure. Inventory evidence does not approve a release.

### Breaking Changes

No existing interface is intentionally broken. Consumers replacing checkout-based generators must
account for committed-only semantics and schema differences rather than treating outputs as
interchangeable. Pin a tested immutable revision containing the new command before adoption.

### Deprecations

No deprecations are introduced in this release.

## Support Boundary

Python support remains >=3.13,<3.15. Generation requires local Git and a top-level working tree;
bare repositories, nested roots and empty commit trees are unsupported. Paths must decode as UTF-8.
Regular/executable files and symlink text are supported; submodule contents and external Git LFS
payloads are not collected. No network fetch, package installation or cloud credentials are used
by inventory generation. Build and clean-install validation retain their separate dependency
resolution boundary.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. Versions continue to derive from Git through setuptools-scm; preparation does not add
a version constant, create a tag, publish packages or dispatch hosted workflows.

No data migration is required. Add generation alongside existing controls and inspect both formats
before replacing local generators. Generate evidence and source archives from the same resolved
commit. To roll back adoption, restore the previous verified pin and generator through review;
existing read-only checks remain available. Preserve immutable tags.

## Known Limitations and Follow-Up

These reports describe committed source/assets, not transitive dependencies, linked frameworks,
installed packages or compiled products. Checksums establish identity, not authenticity, license
rights, correctness or release readiness. Review paths and hashes before sharing evidence.

Each Git invocation has a 120-second timeout. Blob output is held in memory, so large repositories
may require substantial memory. Missing objects fail without fetching; symlinks are never followed
and LFS pointers remain pointer blobs. SPDX output is intentionally not byte-for-byte reproducible.
No independent SPDX schema-validation result is claimed by renderer assertion tests alone.

Complete final committed-tree packaging, eventual tag/version agreement and hosted Python/platform
validation before release closeout. Local checks do not establish hosted success or publication.
