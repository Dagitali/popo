# Popo v0.1.2

Version 0.1.2, tagged on 2026-09-24 (UTC), fixes the quality-gate failure caused by a test requiring
a Dependabot exclusion that is absent from configuration. See the [changelog] for the concise change
list.

- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

Changes are limited to the obsolete workflow-contract test and documentation. Dependabot already
allows fixture updates; this release does not add an exclusion or change its schedules. The runtime
dependency checker and its tests for matching and mismatched minimums remain intact.

## Compatibility and Configuration

No CLI, configuration-key, diagnostic, or exit-code changes. `packaging>=26.3,<27` and the
`packaging==26.3` lowest-dependency pin remain unchanged from 0.1.1. This release does not raise the
minimum again.

When accepting a Dependabot pin increase, update the corresponding metadata lower bound in the same
pull request and document the compatibility impact. CI must reject inconsistent files.

## Support Boundary

Python 3.13 and 3.14 support and read-only repository checking are unchanged. There are no new
cloud, credential, or platform requirements.

## Validation

Interpret these results using the [evidence boundaries].

At preparation time, the final candidate commit was pending. The release checklist required its
identity and completed evidence for:

- `make check` for lint, typing, tests, and repository consistency;
- `make docs-markdown` and `make release-changelog RELEASE_VERSION=v0.1.2`;
- `make check-release` for both built distributions, metadata checks, and clean installations; and
- Hosted validation and artifact-integrity gates described in the [release policy].

Hosted validation and publication results were not recorded.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations].

If further corrections are needed before release, amend the candidate and rerun checks. After
release, prepare a follow-up version rather than moving the tag. Reverting the test removal alone
would restore the known failure, so review the test and policy together. No consumer-data migration
or rollback is required.

## Known Limitations and Follow-Up

- Dependabot may update the fixture without updating metadata, requiring a maintainer edit before CI
  passes. The consistency gate remains intentional.
