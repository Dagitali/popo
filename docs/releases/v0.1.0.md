# Popo v0.1.0

Version 0.1.0, tagged on 2026-09-24 (UTC), introduces the repository-policy CLI and its development

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

This release introduces the `src/popo/` package, command-line entry points, consumer configuration,
tests, packaging, Make targets, optional hooks, and GitHub automation. Contributor and release
documentation explain the same interfaces and validation boundaries. The [changelog] retains the
detailed change list, including interpreter-selection and module-rename corrections.

Popo checks repositories; it does not deploy infrastructure or modify consumer files. Its own
development policy does not prescribe a consumer's programming language, cloud, or branching model.

## Compatibility and Configuration

The [initial scaffold] contained no installable CLI, so there is no prior tagged CLI interface to
migrate. Use `popo` or `python -m popo`; each check accepts `--root`. Consumer settings live under
`[tool.popo]` in the inspected repository's `pyproject.toml`. See the [README] for commands,
dependency modes, and configuration examples.

`check-all` combines Markdown, action-pin, dependency, and Python-policy checks. Release-changelog
validation is separate and requires a release argument, for example `popo check-release-changelog
v0.1.0`. It expects a dated heading such as `## [0.1.0] - 2026-09-24`; retain the brackets required
by this checker.

## Support Boundary

The package declares Python 3.13 and 3.14 support and alpha development status. Some checks are
specific to Python metadata or GitHub Actions; language- and cloud-neutral design does not imply
that every ecosystem is already supported. Checks require no cloud credentials.

Make-based contributor workflows require Make and a POSIX-compatible shell. Cross-platform package
installation tests are distinct from those local tooling requirements; see the [contributing guide].

## Validation

Interpret these results using the [evidence boundaries].

At preparation time, the final candidate commit was not recorded. The release checklist required
that commit and completed evidence for:

- `make check` and `make docs-markdown`;
- `make release-changelog RELEASE_VERSION=v0.1.0`;
- `make check-release`, including wheel and source-distribution builds, `twine check`, and clean
  installation tests against those same artifacts; and
- The applicable hosted validation matrices and artifact-integrity checks in the [release policy].

Completed distribution validation and publication were not recorded.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations].

Checks are read-only, so running them requires no consumer-data rollback. If adopting this candidate
blocks a consumer workflow unexpectedly, restore that consumer's previous tool configuration while
investigating and prepare a corrected candidate or follow-up version. Do not move a released tag.
The `v0.0.0` scaffold is not an installable package rollback target.

## Known Limitations and Follow-Up

- Markdown validation checks local links and anchors, not external URL availability.
