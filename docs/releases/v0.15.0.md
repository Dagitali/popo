# Popo v0.15.0

Version 0.15.0 adds opt-in Apple metadata contracts and strengthens parsing, shared validation and
regression suites. This minor release is dated 2026-11-04 and documented in released form at the
maintainer's request. Tagging and publication remain separate operations.

## Highlights

Use `popo check-apple-metadata` to validate typed XML/binary plist expectations and explicit Xcode
project or target settings. Select the command directly or through an explicit `check-all` profile.
See the [Apple metadata guide] for policy examples and the [changelog] for complete dated scope.

## Change Scope

Add confined literal paths, exact typed plist comparisons, required absence checks, explicit Xcode
configuration selection and consistency checks. Report independent rule failures with redacted
values through the existing text/JSON reporting contracts.

Reuse successful and failed metadata reads/parses within one validation run and refresh inputs on
later runs. Index referenced Xcode configurations once, retaining requested order and settings
identities. Reject ambiguous selected names while allowing unused duplicate names. Reject unquoted
OpenStep structural delimiters used as values or keys while preserving quoted punctuation.

Compile boundary identifier patterns once per policy load while retaining native Python dotted names
and Swift identifiers. Consolidate Apple parser, configuration and CLI regression suites with named
cases, exact diagnostics, unique mutations and unchanged-input assertions. Share restricted-
platform symlink fixtures across unit and integration tests without hiding unexpected errors.

## Compatibility and Configuration

The new optional capability justifies a minor bump from v0.14.0. Existing command defaults and
profiles remain unchanged. Apple metadata checks require explicit policy and are not selected by
legacy defaults; direct invocation without policy fails. Versions continue to derive from Git tags
through `setuptools-scm`; no second release-version source is introduced.

### Breaking Changes

No intentional existing command, configuration or runtime removal is introduced. The new metadata
checker rejects malformed OpenStep syntax and invalid or empty policies rather than accepting
unsupported inputs. Internal checker modules remain implementation details.

### Deprecations

No new deprecation or support-window commitment is introduced.

## Support Boundary

Popo requires Python >=3.13,<3.15. Native checks remain offline and read-only. Apple metadata checks
read consumer-owned files without Xcode, signing tools or credentials. Python and Swift retain their
native syntax and identifier differences.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. This preparation creates no tag or hosted release and publishes no package. No data
migration is required. Adopt the reviewed pin and explicit consumer policy; roll back by restoring
the prior verified dependency pin and matching policy.

## Known Limitations and Follow-Up

Apple metadata checks inspect literal settings, not resolved Xcode build settings. They do not
expand variables, resolve inherited settings or xcconfig files, inspect signatures or provisioning,
validate schemes/test plans, or establish legal export compliance. Consumer-native build, signing
and deployment checks remain necessary.

Rebuild and validate the final committed/tagged tree, intended version and release record before
delivery. Local validation does not establish hosted Linux/Windows or Python 3.13 success.
