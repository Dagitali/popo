# Popo v0.14.0

Version 0.14.0 adds read-only LLVM/Xcode coverage summaries and streamlines shared validation and
regression suites. This minor release is dated 2026-10-31 and documented in released form at the
maintainer's request. Tagging and publication remain separate operations.

## Highlights

Use `popo coverage-summary` to summarize existing LLVM or xccov JSON exports as Markdown or JSON.
Explicit include/exclude patterns select POSIX source paths. The command reads exported data;
consumers retain ownership of test execution, report export and percentage gates. See the [coverage
guide] for adapters, selection rules and output contracts, and the [changelog] for the complete
dated scope.

## Change Scope

Add explicit LLVM/xccov adapters, redacted failures and aggregate coverage reporting. Aggregate
records by distinct selected path with LLVM addition, Xcode best-count selection, adapter-specific
zero-total handling and record-validation error precedence. The command remains separate from
`check-all` and cannot be selected through check profiles.

Stream source inspection and text reports; reuse boundary-read caches, bound source-guide matching
and mask Swift noncode with translation tables. Simplify callable documentation checks, scoped
Python/Swift toolchain literals, dependency-layout discovery, immutable automation defaults and YAML
graph traversal. Preserve diagnostic order and duplicates, Unicode positions, LF boundaries, JSON
schemas, exit codes, scope precedence, explicit empty arrays and native language differences.

Correct Python generator documentation requirements for yields in nested defaults, decorators and
class-header expressions while excluding nested callable bodies. Resolve actionlint temporary views
before tool execution so canonicalized paths on both output streams map back correctly through
symlinked temporary roots, including macOS `/private` aliases.

Consolidate class-based parameterized tests and isolated fixtures across configuration, source,
Markdown, dependencies, npm, safety, hosted evidence and CLI dispatch. Strengthen exact diagnostics,
process-launch guards, unique mutations, read-once and unchanged-input assertions. Split the
oversized source-parity suite without discarding documentation or comments. Cover independent
success/failure cases, deferred iterator errors, native Python/Swift facts, source-guide reads,
standalone-policy precedence, header preambles, Markdown anchors and npm specification shapes.

## Compatibility and Configuration

The optional coverage-reporting capability justifies a minor bump from v0.13.0. Existing commands,
profiles, configuration keys, package-root exports and text/JSON check-result schemas retain their
contracts. Coverage-summary JSON is a separate reporting document, not a native-check result or a
committed-source inventory. Distribution versions continue to derive from Git through
`setuptools-scm`; no second release-version source is introduced.

### Breaking Changes

No intentional command, configuration or supported-runtime removal is introduced. Python generator
classification can identify documentation violations previously missed in definition-time
expressions. Consumers must correct affected NumPy contracts. Coverage adapters validate exported
counts and selected records; they do not establish that tests passed or that a complete native
coverage graph was exported.

### Deprecations

No new deprecation or support-window commitment is introduced. Internal checker modules remain
implementation details; adoption examples continue to use the public CLI.

## Support Boundary

Popo requires Python >=3.13,<3.15. Native checks remain offline and read-only. Coverage summaries do
not invoke compilers, LLVM, Xcode or test tools, read source files, write artifacts or install
dependencies. Python retains native AST semantics; Swift retains Tree-sitter syntax and bounded
recovery rather than compiler or runtime guarantees. Actionlint remains a separately invoked,
maintainer-installed external validator operating on a disposable compatibility view.

## Validation

Local validation used macOS 27.0.1 arm64 with Python 3.14.8 against the preparation checkout,
including release-document edits. The shared release playbook and Python-package record template
were reviewed. Results describe this checkout, not a v0.14.0 tag or hosted release.

- `make release-changelog RELEASE_VERSION=v0.14.0`, `make docs-markdown` and `git diff --check`
  passed. Documentation is checked again after recording final artifact results.
- Lint, formatting, typing, repository policy and all 2,633 deterministic unit/integration tests
  passed with 100% statement and branch coverage: 3,116 statements and 1,150 branches across 57
  source modules.
- `make check-release PYTHON_DIST_DIR=/tmp/popo-v0140-release-c_xts4t5` with `TEST_ARGS='--cov=popo
  --cov-report=term-missing'` built fresh wheel and sdist artifacts. Both passed Twine metadata
  checks. The complete release gate passed, including all 242 artifact cases: 2 distribution
  contracts and 240 clean-installation, installed-command and consumer-example tests.
- Artifact tests execute installed subprocesses. Their separate parent-process coverage report does
  not measure the deterministic source suite's statement or branch coverage.
- The initial sandboxed build could not resolve PyPI while installing isolated build dependencies.
  The gate was retried with authorized network access. No package was published or hosted workflow
  dispatched; no hosted cross-platform result is claimed.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.
Validate fresh wheel and source distributions, Twine metadata and clean installations. Keep build
artifacts separate from generated coverage summaries. A development artifact's SCM version is not
proof that a future v0.14.0 tag will produce the intended release metadata.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized immutable tagging and
optional publication. This preparation creates no tag or hosted release and publishes no package. No
consumer data migration is required. Adopt the reviewed dependency pin and validate local/CI entry
points. Roll back by restoring the prior verified pin and matching consumer policy.

## Known Limitations and Follow-Up

Rebuild and validate the final committed/tagged tree, including this record and intended version,
before delivery. Local macOS validation does not prove Linux/Windows or Python 3.13 results.
Publication and hosted cross-platform checks remain separate operations. Consumer-native test,
compiler and packaging checks remain necessary; declaration parity does not execute those tools.
