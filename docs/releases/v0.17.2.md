# Popo v0.17.2

Version 0.17.2 aligns shared Python tooling conventions while retaining package and consumer policy.
This patch release is dated 2026-11-07 and documented in released form at the maintainer's request.
Tagging and publication remain separate operations.

## Highlights

Python tool tables are ordered alphabetically, with reusable pytest/Ruff defaults distinguished from
package configuration and native consumer policy. The pytest configuration minimum is 9.1, within
the existing development requirement of >=9.1.1. See the [contributor guide] and [changelog].

## Change Scope

Alphabetize all `[tool.*]` tables while keeping their comments attached and preserving values and
array ordering. Align pytest's minimum from 9.0 to 9.1; the development dependency already requires
=9.1.1. Keep strict import/configuration options and Ruff defaults aligned with the native consumer
without importing its source paths, warning policy, E501 exception or application contracts.

Document reusable-default boundaries and repository-owned settings. Preserve build metadata,
SCM-derived versions, dependencies, console entry points, package discovery/data, supported Python
versions, default test layers, opt-in artifact layers, coverage, strict typing and lint selection.

## Compatibility and Configuration

This patch changes contributor configuration and documentation. Installed commands, native policy
schemas, text/JSON reporting and exit codes retain their contracts. Test execution now requires
pytest >=9.1, already satisfied by the development extra. Tool-table ordering has no parsed TOML
semantic effect. Versions continue to derive from Git tags through `setuptools-scm`.

### Breaking Changes

No intentional runtime, CLI or consumer-configuration removal is introduced. Environments invoking
tests directly with pytest 9.0 must update to >=9.1; supported development installations already
require >=9.1.1. Python runtime requirements remain unchanged.

### Deprecations

No new deprecation or support-window commitment is introduced.

## Support Boundary

Popo requires Python >=3.13,<3.15. Native checks remain offline and read-only. Package-specific
build, typing and coverage settings remain distinct from native consumer policies. No consumer
application identity, deployment commitment or warning/lint exception is copied into Popo.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.
Validate fresh wheel and source distributions, Twine metadata and clean installations. Development
SCM versions do not establish metadata produced by the eventual immutable v0.17.2 tag.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. This preparation creates no tag or hosted release and publishes no package. No data
migration is required. Adopt a reviewed immutable dependency pin and matching contributor setup;
roll back by restoring the prior verified pin and configuration.

## Known Limitations and Follow-Up

A shared configuration repository should provide reusable defaults or templates while retaining
consumer-specific metadata and policy. Complete package and native-app TOML files are not
interchangeable. Taiscora remains unchanged by this work. Shared-default organization does not
establish hosted enforcement or remove the need for consumer-native checks.

Rebuild and validate the final committed/tagged tree, intended version and release record before
delivery. Local validation does not establish hosted Linux/Windows or Python 3.13 success.
