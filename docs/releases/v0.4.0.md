# Popo v0.4.0

Version 0.4.0, tagged on 2026-10-05 (UTC), adds native `$/` self-repository reference validation and
read-only actionlint compatibility. It covers the complete
`feature/add-self-reference-support-and-actionlint-compatibility` branch since `v0.3.7`. This
retrospective record was prepared on 2026-10-04 for the planned 0.4.1 patch release after tagging;
it was absent from the original tag. See the [changelog] and [published tags].

## Change Scope

The release updates action-pin validation, automation target resolution, and CLI dispatch, and adds
the actionlint adapter. The adapter uses parsed YAML locations to rewrite self-reference values in
temporary automation files and includes referenced local targets and actionlint configuration.
Consumer source files remain unchanged, and workflow commands are never executed.

Unit tests cover self-reference syntax, containment, targets, inputs, and normalization. Integration
tests cover CLI errors, diagnostic mapping, tool statuses, and source preservation. README,
configuration guidance, and changelog describe the new behavior. Dependencies, packaging metadata,
and hosted workflows are unchanged in the tagged change set.

## Compatibility and Configuration

This minor release adds accepted reference syntax and a public command. No consumer schema changes
or migration are required. Self-reference paths must be nonempty, revision-free, and free of
traversal; local targets must remain within the supplied checkout.

`popo check-actionlint --root .` selects configured workflow/template globs by default. Optional
positional paths select root-relative or absolute in-root files, and `--actionlint` selects the
installed executable and options. Tool output retains its streams and exit status; source or tool
setup errors reported by the CLI return status one. The command is separate from `check-all` and
does not install tools. See the [configuration guide].

## Support Boundary

No runtime support-boundary changes. Python remains `>=3.13,<3.15`. The external actionlint
executable is consumer-provided. Popo inspects the supplied checkout and does not verify remote or
historical revision availability; the compatibility adapter does not add hosted-platform support for
self-reference syntax.
