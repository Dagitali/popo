# Popo v0.2.1

Version 0.2.1, tagged on 2026-09-26 (UTC), corrects the artifact-build command used by
cross-platform installation tests. See the [changelog] for the release entry.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The implementation change is limited to `tests/support/artifacts.py`. The invalid option caused the
build command to exit with status 2 during fixture setup, before installation tests ran. The
corrected command builds temporary wheel and source distributions for metadata validation and
isolated installation tests.

The existing `--artifact-dir` test option and Linux CI's prebuilt-artifact path are unchanged.
Workflow triggers, permissions, and release gates are unchanged; no check is bypassed.

## Compatibility and Configuration

No consumer compatibility or configuration changes. CLI commands, flags, output, exit codes, and
repository-check behavior remain unchanged. No migration or new configuration is required.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`, and the runtime dependency remains
`packaging>=26.3,<27`. The fix affects contributor and CI test infrastructure, not package runtime
behavior or supported platforms.

## Validation

Interpret these results using the [evidence boundaries].

Preparation began from the branch state before the working-tree artifact-fixture correction and
release documentation. The final release commit was not yet set at preparation time.

Before these release documents were added, the fixture correction passed locally on macOS with
Python 3.14.6 on 2026-09-26:

- `make test-distribution test-installation`: 2 distribution tests and 12 clean-installation tests;
- `make check`: all 215 unit/integration tests, lint, formatting, strict typing, and self-checks;
- `make docs-markdown` and `git diff --check`.

The preparation checklist required `make release-changelog RELEASE_VERSION=v0.2.1` and `make
docs-markdown` for the release documents, recording the final candidate commit, and `make
check-release` with a fresh `PYTHON_DIST_DIR` to validate the same built artifacts across the
artifact suites. The earlier local tests are not proof about a later commit or a tagged 0.2.1
distribution.

Hosted macOS and Windows CI and the tagged release gates, including the wheel-version match,
remain to be verified under the [release policy]. No hosted success is asserted here.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations].

Reverting the fixture correction would restore the build failure. Prefer a new corrective release if
another issue is discovered; do not disable the clean-installation tests to pass CI.

## Known Limitations and Follow-Up

- Local macOS results do not establish that hosted Windows or macOS jobs pass.
