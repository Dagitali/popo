# Popo v0.8.0

Version 0.8.0 adds consumer-owned required-file and source-header policies. This release text was
prepared in released form for 2026-10-23. The annotated tag is now present locally; publication is
not established by that tag or the preparation-time validation recorded below.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

Add read-only `check-required-files` and `check-file-headers` commands, configuration loaders,
regression tests and installed-CLI coverage. Required paths are exact repository-relative filenames.
Header rules support consumer identity templates, comment formats, first-line directives and
reasoned preservation exceptions. Configured checks also participate in `check-all`.

Align local Ruff-hook dependency bounds with the existing development extra. Update release
history to reflect the existing v0.7.0 tag and its separately verified local validation.

## Compatibility and Configuration

Both capabilities are opt-in. Existing consumers retain their behavior until they configure
`[tool.popo.files]` or `[tool.popo.headers]`. Explicit commands require their own configuration;
missing policy, malformed settings or violations return exit status one. Successful checks return
zero. No Python package metadata is required for either file-policy command.

See [file policies] for configuration, templates, matching order, directives and preservation
exceptions. The checks inspect files without rewriting them. No deprecations or required migration
are introduced; retain consumer-specific validators until equivalent coverage is verified.

### Breaking Changes

No breaking changes are recorded for this release. Compatibility and adoption details are described
above.

### Deprecations

No deprecations are recorded for this release.

## Support Boundary

Python remains `>=3.13,<3.15`. Runtime dependency bounds, packaging formats and publication
safeguards are unchanged. Python 3.15 support is outside this release.

## Validation

Interpret these results using the [evidence boundaries].

The preparation checkout passed `make docs-markdown`, `make release-changelog
RELEASE_VERSION=v0.8.0` and `make check-release` on macOS/Python 3.14.8: 524 unit/integration tests,
30 artifact/clean-install tests, lint, formatting, strict typing and repository policies passed.
Fresh wheel and source distributions passed Twine validation and installed-CLI checks, including
the new file-policy commands.

The distributions carry a Git-derived development version, not `0.8.0`; these results do not prove
the eventual tag's version. New untracked documentation must be committed before final artifact
validation. Python 3.13, hosted cross-platform checks, annotated-tag version matching and
publication were not exercised in this preparation run. They require separate release evidence.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]; Popo's [release policy] retains
its local gates and opt-in safeguards. This documentation does not create a tag or publish a
GitHub Release. Distribution versions continue to derive from Git tags through `setuptools-scm`.

Adoption requires consumer-owned configuration and a verified released immutable dependency pin.
To roll back, restore the previous pin and any local validators replaced during adoption; remove
unsupported file-policy invocations and configuration. Keep existing release tags immutable.

## Known Limitations and Follow-Up

Header matching validates literal configured structure, not the accuracy of prose. First-match
rules and explicit exceptions require consumers to classify maintained files. Git discovery has a
bounded recursive fallback; binary assets need preservation exceptions. These checks do not infer
policy or replace language-specific semantic validators.

Complete annotated-tag version matching and hosted validation before recording release completion.
Record publication evidence separately if publication is authorized.
