# Popo v0.7.0

Released as annotated tag [v0.7.0] on October 22, 2026 (UTC), following integration into `develop`
and `main`. Markdown consumers can consolidate local reference-label and inline-image checks into
the existing public `check-docs` command.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

Validate inline image destinations using the existing repository-containment rules. Reject
undefined full/collapsed reference labels and conflicting destinations after case and whitespace
normalization. Ignore inline code and HTML comments without losing original diagnostic line
numbers; comment delimiters inside code examples remain literal. Expand regression and installed
CLI coverage. The release-record gate accepts `release/prepare-MAJOR.MINOR.PATCH` while retaining
legacy release names and dated-record validation. No tools fetch external documentation or modify
consumer files.

## Compatibility and Configuration

### Breaking Changes

`check-docs` and `check-all` become stricter: previously accepted undefined labels, conflicting
reference definitions and missing or escaping inline images now fail with exit status one. Repair
those Markdown sources before upgrading. CLI commands, flags, configuration and success/failure
status conventions are unchanged. Generated heading IDs require no HTML anchor tags.

### Deprecations

No deprecations.

## Support Boundary

Python remains `>=3.13,<3.15`, with unchanged runtime dependency bounds. Separate Python 3.15 work
is excluded. Local validation covers macOS with Python 3.13 and 3.14; hosted Linux/Windows execution
must be verified separately. Tagged artifacts were validated locally on Python 3.14.8.

## Validation

The implementation passed 453 unit/integration tests on Python 3.13 and 3.14, lint, formatting,
strict typing and repository checks. On Python 3.14 it passed two artifact tests and 24 installed
CLI tests using freshly built wheel and source distributions. Pre-commit and the existing Swift
app consumer's Markdown check also passed during candidate preparation.

The exact v0.7.0 tagged tree subsequently passed `make release-changelog RELEASE_VERSION=v0.7.0` and
`make check-release` in a separate temporary checkout on macOS/Python 3.14.8: 453 unit/integration
tests and 26 artifact/clean-install tests passed, alongside lint, formatting, strict typing and
repository policies. Fresh wheel and source distributions both identified as `0.7.0` and passed
Twine validation. The initial isolated build could not download dependencies under restricted
network access; the retry with network access passed. These local results do not establish hosted
cross-platform success or publication. This record update does not alter the tag.

Wheel/sdist formats, console/module entry points, metadata, typing marker and license contracts
are unchanged. The CD workflow builds one artifact pair, validates installation, checks tag/version
agreement, generates a runtime SBOM and checksums, and retains artifacts for 14 days. An eventual
published GitHub Release may attach those artifacts through the opt-in protected publication job.

## Deployment and Rollback

The annotated v0.7.0 tag is present locally and on GitHub, and its commit is reachable from `main`.
GitHub Release publication and hosted validation have not been verified in this record. Follow the
[release policy] for optional protected publication; tagging and local validation do not establish
publication. Preserve the existing tag and publication safeguards.

Before adopting, verify the released immutable dependency pin and the validation relevant to the
consumer. Roll back an adoption by restoring the previous pin and its complementary local checks; do
not move or replace the release tag.

## Known Limitations and Follow-Up

Shortcut references and nested/escaped link syntax remain incompletely parsed; this is a bounded
checker rather than a complete Markdown renderer or an external URL checker.

Verify hosted CI/CD results and retained artifacts, and record publication evidence if publication
is authorized. New required-file/header capabilities and Python 3.15 support are outside this
release; keep later changes under `Unreleased` until a separate version is prepared.
