# Popo v0.6.1

Version 0.6.1, tagged on 2026-10-07 (UTC), updates the Commitizen and mypy pre-commit hooks. This
retrospective record backfills the tagged release's missing changelog section and release notes in
the maintained checkout; the original tagged tree remains unchanged.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The complete diff from `v0.6.0` to `v0.6.1` changes only `.pre-commit-config.yaml`, through
[Dependabot PR #5]. Commitizen advances from `v4.19.0` to `v4.19.1`; the mypy mirror advances from
`v2.3.1` to `v2.4.0`. Existing hook stages, arguments, and other revisions are preserved.

## Compatibility and Configuration

No Popo CLI or consumer-configuration changes. Commands, diagnostics, exit codes, runtime
dependencies, and opt-in safety checks retain their 0.6.0 behavior. Contributor hooks use the
updated tools; consumers do not need to migrate their Popo configuration.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`. These hook updates do not alter package
dependency constraints or establish additional runtime support.

## Validation

Interpret these results using the [evidence boundaries].

Local annotated tag metadata and the full `v0.6.0` to `v0.6.1` diff were inspected on 2026-10-07.
The maintained checkout passed `make docs-markdown`, `make release-changelog
RELEASE_VERSION=v0.6.1`, `make check` (425 unit/integration tests, lint, formatting, strict typing,
and repository checks), and `git diff --check` on that date. Historical hook execution, distribution
builds, clean installations, and hosted validation or publication results were not verified.
Artifact checks were not rerun for this documentation-only backfill; current-checkout checks do not
validate the immutable tagged artifacts.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]. Contributors refresh their
pre-commit environments to use the updated hooks. If an update causes a regression, restore the
previous hook revision through a reviewed follow-up change and preserve existing release tags.

## Known Limitations and Follow-Up

The original `v0.6.1` tag lacks its dated changelog section and versioned release document; this
backfill repairs maintained history without repairing that tagged tree. See
[Validation](#validation) for historical evidence gaps.
