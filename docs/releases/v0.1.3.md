# Popo v0.1.3

Version 0.1.3, tagged on 2026-09-24, updates the Commitizen and Ruff pre-commit hooks. This
retrospective record documents the hook changes and the missing changelog entry that caused CD
validation to fail. See the [changelog] and the subsequent [v0.1.4 correction].

## Highlights

- Update the Commitizen hook from v4.18.0 to v4.18.1.
- Update the Ruff hooks from v0.16.7 to v0.16.8.

## Change Scope

The tree diff from `v0.1.2` to `v0.1.3` changes only the two remote hook revisions in
`.pre-commit-config.yaml`. There are no package implementation, test, dependency-bound, or workflow
changes in that diff.

The tag annotation describes broader Dependabot and release-documentation work, but the tagged tree
comparison establishes the incremental scope recorded here. This retrospective document does not
rewrite the annotation or the tag.

## Compatibility and Configuration

No CLI, consumer configuration, diagnostic, or exit-code changes. Contributors using the configured
remote hooks receive the updated tool versions. No consumer migration is required.

## Support Boundary

Python 3.13 and 3.14 support, the runtime dependency `packaging>=26.3,<27`, and read-only repository
checks are unchanged. Hook updates affect contributor tooling, not runtime dependencies.

## Validation

The annotated tag and date are verified from repository history. Inspection of `git diff v0.1.2
v0.1.3 -- .pre-commit-config.yaml` confirms the two hook updates. Inspection of `git show
v0.1.3:CHANGELOG.md` confirms that the tagged changelog lacks a dated 0.1.3 section.

The maintained [changelog] records the resulting CD failure. Version 0.1.4 backfills the entry in a
later tree; checking that retrospective entry today does not validate the original tag. No
historical passing test, artifact-build, installation, or publication result is asserted here.

## Deployment and Rollback

Keep the original tag unchanged. Rerunning its changelog gate against the same checkout encounters
the same missing section; use the [v0.1.4 correction] rather than moving or reusing `v0.1.3`. This
retrospective record does not trigger publication or require a consumer-data rollback. Any future
release operation remains governed by the [release policy].

## Known Limitations and Follow-Up

- This document is a historical reconstruction, not content included in the original tag.
- The missing dated section remains part of the original tagged tree; later documentation does not
  repair that historical validation result.
