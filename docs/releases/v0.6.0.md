# Popo v0.6.0

Version 0.6.0, released on 2026-10-07, adds opt-in, offline repository safety checks for GitHub
workflows and npm manifest consistency.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The release adds `check-repository-safety`, the `[tool.popo.safety]` configuration loader, and
configured safety validation in `check-all`. Unit and integration coverage accompanies the new
command, configuration, workflow checks, and npm consistency checks. The [safety reference]
documents configuration, reviewed exceptions, and static-analysis limits.

Workflow checks require scoped, dated exceptions for `pull_request_target` and `workflow_run`,
reject direct pull-request head checkouts in privileged workflows, and detect direct event-data
interpolation in shell commands. npm checks compare configured manifests with v2/v3 lockfile root
metadata and check resolved versions for exact dependency pins. Checks read local files without
network access, package installation, or workflow execution.

## Compatibility and Configuration

The new command accepts `--root` and requires an explicit `[tool.popo.safety]` table. Its
`workflow-globs`, `exceptions`, and `npm-pairs` arrays default to empty. Success returns zero;
validation or configuration failures return one with diagnostics. Unknown settings and malformed
configuration fail.

Existing consumers retain their aggregate behavior until they configure the safety table. Opted-in
consumers receive safety diagnostics through `check-all` and must address failures or supply valid
reviewed trigger exceptions. Exceptions do not permit direct privileged pull-request head checkouts
or prohibited shell interpolation. No migration is required for consumers that do not opt in.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`, and runtime dependency constraints retain
their existing configuration. npm consistency validation supports lockfile versions 2 and 3.

## Validation

- `make release-changelog RELEASE_VERSION=v0.6.0` for the dated release section.

`make check-release` was not run for this documentation-only preparation; distribution builds and

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]. Consumers enable checks by adding
`[tool.popo.safety]` and selecting workflows and npm pairs in their own repository. No data migration
or hosted settings change is required. Removing the table disables aggregate safety validation;
remove explicit invocations when reverting to a version without the command. Correct release defects
through a reviewed follow-up version.

## Known Limitations and Follow-Up

These checks do not establish workflow trust or approval authenticity and do not provide complete
taint analysis. Indirect checkout and artifact flows, alternate event contexts, and third-party
actions still require review. npm ranges, peer resolution, workspaces, transitive graphs, and
platform-specific optional packages are not fully validated; retain `npm ci` and runtime checks.
See [Validation](#validation) for outstanding release evidence.
