# Popo v0.3.4

Version 0.3.4, tagged on 2026-10-01, updates the Commitizen and Ruff pre-commit hooks through [PR
#3]. This patch candidate covers the complete change set since `v0.3.3`. The intended tag is
`v0.3.4`; it has not been created. See the [changelog].

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Update the Commitizen hook from `v4.18.1` to `v4.19.0`.
- Update the Ruff pre-commit hook revision from `v0.16.8` to `v0.16.9`.
- Retain existing hook stages, arguments, and local Make-based checks.

## Change Scope

The merged Dependabot update in [PR #3] changes only two `rev` values in `.pre-commit-config.yaml`:
`commitizen-tools/commitizen` and `astral-sh/ruff-pre-commit`. Commitizen remains a commit-message
hook; Ruff remains part of the contributor lint/format workflow. The Ruff hook update aligns with
the existing `ruff>=0.16.9,<0.17` development requirement and local managed-hook constraint, neither
of which changes in this release.

This release preparation adds the versioned record, dated changelog entry, and archive index entry.
Package source, tests, runtime dependencies, consumer policy, and GitHub workflow implementation are
unchanged.

## Compatibility and Configuration

No Popo CLI or consumer-configuration changes. Commands, flags, diagnostics, exit codes, and
`[tool.popo]` settings retain their behavior. No consumer migration is required.

Contributors using pre-commit receive the selected tool revisions when their hook environments are
prepared. Tool diagnostics may differ between upstream versions; existing hook selection and stages
remain intact. This update does not enable new Commitizen options or change Ruff rules.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`, with runtime dependencies
`packaging>=26.3,<27` and `PyYAML>=6.0.3,<7`. Hook revisions affect development tooling rather than
the installed Popo CLI's runtime requirements.

## Validation

Local validation on 2026-10-01 passed against the 0.3.4 working-tree candidate:

- `python -m pre_commit validate-config` passed using the repository's development environment.
- `make release-changelog RELEASE_VERSION=v0.3.4` found the matching dated entry.
- `make docs-markdown` passed local link and heading-anchor validation.
- `make check-release` with a fresh temporary `PYTHON_DIST_DIR` passed lint, formatting, strict
  typing, all 274 unit/integration tests, repository checks, wheel/source builds, `twine check`,
  and all 18 artifact/clean-install tests.
- `git diff --check` passed; reference definitions are sorted and unique, and earlier dated
  changelog entries are preserved.

The release gate used network access for isolated build and installation dependencies. Built
artifacts have a Git-derived development version, not final `0.3.4`; these results do not establish
agreement with the eventual tag, hosted platform success, or publication. Configuration validation
does not execute the managed Commitizen or Ruff hook environments; those were not run in this
validation session. This results wording was added after the artifact run and rechecked with the
Markdown and changelog gates.

## Deployment and Rollback

No cloud deployment, data migration, or PyPI publication is introduced. Authorized tagging triggers
release validation; GitHub publication retains its separate manual opt-in and environment safeguards
in the [release policy]. A candidate record does not establish tagging or publication.

If a hook regression requires rollback, restore only the affected revision through a reviewed
follow-up change and rerun the relevant checks. Preserve existing release tags and document the
correction in a subsequent version.

## Known Limitations and Follow-Up

- Verify the finalized candidate and eventual tag's artifact version before publication.
- Local source and artifact checks do not establish hosted cross-platform results or execution of
  every managed pre-commit hook.
- Follow the [release playbook] and update the [release archive] from verified evidence.
