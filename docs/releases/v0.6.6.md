# Popo v0.6.6

Version 0.6.6, released on 2026-10-08, centralizes reusable engineering documentation in Dagitali
Engineering while preserving Popo's community-health files, agent instructions, and local contracts.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The release removes sixteen local copies of shared engineering documentation: development workflow,
task templates and index, change management, interface review, required-check transitions, evidence
inventory and release-note templates, learnings, references, release and incident-response
procedures, testing, onboarding, branch protection, and release policy.

Shared Markdown links follow Engineering's `main` branch. The [adoption record] maps removed files
to their equivalents and records ownership and maintenance boundaries. Popo-specific setup,
recovery, routing rules, release gates, and publication safeguards move into the retained
[contributor guide]. Navigation and policy references, including links in historical records, are
updated without rewriting historical outcomes.

## Compatibility and Configuration

CLI commands, flags, consumer configuration, diagnostics, exit codes, dependencies, package
metadata, and workflow behavior are unchanged. No package-consumer migration is required.

Links to removed local Markdown paths must use the shared equivalents or the contributor guide's
local policy sections. Popo's contracts remain authoritative; Engineering's own repository policies
do not replace them. Community-health files, agent/Copilot instructions, product-specific guides,
test layout, and release history remain local.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`; shared examples do not change Popo's
runtime support, branching policy, or publication commitments.

## Validation

Interpret these results using the [evidence boundaries].

The preparation checkout passed `make docs-markdown`, `make release-changelog
RELEASE_VERSION=v0.6.6`, `make check` (426 unit/integration tests, lint, formatting, strict typing,
and repository checks), and `git diff --check` on 2026-10-08.

Artifact and clean-installation checks were skipped because the release changes documentation
ownership and navigation rather than package behavior or metadata. Tag-version matching, hosted
cross-platform validation, and publication remain unverified. Shared destinations were reviewed
against the sibling Engineering checkout; local checks do not establish remote availability or the
future contents of Engineering's `main` branch.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]; Popo's [release policy] retains
its local gates and opt-in safeguards. No data migration or hosted-setting change is required.
Recover incorrect links or lost local requirements through a reviewed correction. Restore a removed
file only if shared guidance cannot cover its required contract; keep existing tags immutable.

## Known Limitations and Follow-Up

Shared links follow a moving branch. Review shared-guide changes against Popo's local requirements
and repair moved paths when needed. See [Validation](#validation) for outstanding release evidence.
