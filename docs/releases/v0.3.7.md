# Popo v0.3.7

Version 0.3.7, tagged on 2026-10-01, modernizes the test suite and strengthens its isolation and
artifact checks. This patch candidate covers the complete `feature/refactor-test-modules` change set
since `v0.3.6`, plus its release preparation. The intended tag is `v0.3.7`; this record does not
establish tagging or publication. See the [changelog].

## Highlights

- Prefix unit, integration, e2e, and meta modules with `test_u_`, `test_i_`, `test_e_`, and
  `test_m_` to reduce cross-layer namespace collisions.
- Group automation tests into cohesive classes and give parameterized scenarios independent setup
  and failure reporting; simplify repeated fixture descriptions and setup.
- Prevent inherited Make overrides, including `TEST_ARGS`, from changing nested test commands.
- Reject incomplete or ambiguous artifact sets before Twine runs, strengthen package metadata
  assertions, and skip symlink tests only for platform restrictions.
- Expand automation regression coverage and keep multi-parameter signatures on separate lines.

## Change Scope

The feature refactors unit, integration, meta, and e2e tests while preserving their scope boundaries
and importlib discovery. Shared unit symlink setup lives in `tests/unit/conftest.py`; helpers
serving one module remain local. Make targets and documentation follow the renamed artifact modules.

Fixtures retain temporary repositories, bounded subprocesses, isolated builds, and clean
installations. Tests cover additional action metadata, local aliases, and action-directory failure
cases. Source changes only reformat a configuration parser signature. README, the [test layout], and
the architecture change-impact map describe the revised suite. Release preparation adds this record,
its dated changelog section, and the archive entry.

## Compatibility and Configuration

No consumer compatibility or configuration changes. CLI commands, flags, accepted inputs,
diagnostics, exit codes, and runtime dependency constraints remain unchanged. No migration is
required for consumers.

Contributors selecting individual modules must use the new filenames. Existing Make targets and
default unit/integration selection remain available. A supplied `--artifact-dir` must contain
exactly one wheel and one sdist before artifact tests run. See the [test layout].

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`; the refactor uses features supported by
the configured pytest 9.1.1 dependency floor. Unit and integration tests remain deterministic and
independent of network access; build and installation layers remain explicit and may download
dependencies. Test classes do not introduce shared mutable state or a new consumer API.

## Validation

Local validation on 2026-10-01 passed against the 0.3.7 working-tree candidate:

- `make release-changelog RELEASE_VERSION=v0.3.7` found the matching dated entry.
- `make docs-markdown` passed local links and heading anchors.
- The PR release-record script passed locally with `release/0.3.7` as its candidate source.
- `make check-release` with a fresh temporary `PYTHON_DIST_DIR` passed lint, formatting, strict
  typing, all 307 unit/integration tests, repository checks, wheel/source builds, `twine check`, and
  all 22 artifact/clean-installation tests.
- `git diff --check` passed.

Runtime checks used Python 3.14.7 and pytest 9.1.1. Built artifacts have a Git-derived development
version rather than final `0.3.7`; these results do not establish eventual tag-version agreement,
hosted Python 3.13 or cross-platform success, or publication. This validation wording was added
after the artifact run and rechecked with the Markdown and changelog gates.

## Deployment and Rollback

No deployment, data migration, or publication behavior changes. Preparing these records does not
authorize tagging or publication; existing safeguards in the [release policy] apply.

Correct test or documentation regressions through reviewed follow-up work and a subsequent release.
Preserve existing tags rather than moving them.
