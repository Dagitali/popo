# Popo v0.1.1

Version 0.1.1, tagged on 2026-09-24 (UTC), aligns Popo's declared `packaging` minimum and
lowest-dependency test pin at 26.3. See the [changelog] for the release entry.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The release updates `pyproject.toml`, `requirements/lowest.txt`, dependency-policy and automation
tests, and public documentation. Dependabot configuration remains unrestricted for the fixture. It
resolves the quality-gate failure caused by upgrading the fixture to 26.3 while metadata still
declared a 25.0 minimum.

No Popo checker implementation, CLI command, flag, configuration key, diagnostic format, or
exit-code contract changes. Repository checks remain read-only; workflow permissions and publication
gates are unchanged.

## Compatibility and Configuration

### Minimum Dependency Change

`packaging>=26.3,<27` replaces `packaging>=25.0,<27`. Versions below 26.3 are no longer supported.
Consumers with older `packaging` pins must update their environment constraints before adopting this
release. Normal dependency resolution installs a compatible version unless another constraint
conflicts. The upper bound remains below 27.

The lowest-dependency fixture now contains `packaging==26.3`. Future intentional minimum increases
must change both metadata and fixture together before merging; see the [contributing guide].
Dependabot may propose the pin update alone, requiring a matching manual metadata edit. The existing
consistency check remains the merge-time safeguard.

## Support Boundary

Python 3.13 and 3.14 support is unchanged. The compatibility change is limited to the declared
`packaging` minimum; there is no new cloud, credential, or consumer-language requirement.

## Validation

Interpret these results using the [evidence boundaries].

At preparation time, the final candidate commit was pending because release changes were still
uncommitted. The release checklist required that commit and validation evidence for:

- `make check`, including regression cases for matching pins and mismatched minimums;
- `make docs-markdown` and `make release-changelog RELEASE_VERSION=v0.1.1`;
- `make check-release`, including both distributions, `twine check`, and clean installations; and
- hosted dependency-boundary and cross-platform checks required by the [release policy].

Hosted release, artifact-integrity, and publication results were not recorded.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations].

Before release, correct the candidate if validation fails. After release, prefer a follow-up version
rather than moving the tag. If a consumer cannot satisfy the new minimum, it can retain its prior
validated Popo version and environment while resolving the constraint conflict. Read-only checks
require no consumer-data migration or rollback.

## Known Limitations and Follow-Up

- Dependabot proposals can fail CI until maintainers align metadata and fixture pins. Accepting an
  increased minimum intentionally drops support for older dependency versions.
