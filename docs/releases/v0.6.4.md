# Popo v0.6.4

Version 0.6.4 adopts Dagitali's organization issue templates by removing Popo's local overrides.
This record was prepared on 2026-10-07 in released form; tagging and publication are unverified.

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The release removes local bug-report, feature-request, and documentation-correction forms and
issue-chooser configuration. README, contributor, and support guidance point to the hosted issue
chooser. A deterministic regression test checks that local issue-template files do not override
organization defaults.

## Compatibility and Configuration

The reporting interface adopts organization defaults, including bracketed title prefixes, required
bug-report version/environment context, optional classification, blank issues, and shared
support/security navigation. Popo's support and security policies remain authoritative.

CLI commands, flags, configuration, diagnostics, exit codes, runtime dependencies, and workflows are
unchanged. Package consumers require no migration. Maintainers must keep local issue-template files
absent to preserve inheritance.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`.

## Validation

Interpret these results using the [evidence boundaries].

The preparation checkout passed `make docs-markdown`, `make release-changelog
RELEASE_VERSION=v0.6.4`, `make check` (426 unit/integration tests, lint, formatting, strict typing,
and repository checks), and `git diff --check` on 2026-10-07.

Artifact and clean-installation checks were skipped because this scope changes repository reporting
and documentation rather than package behavior or metadata. Tag-version matching, hosted
cross-platform checks, publication, and displayed issue-chooser inheritance remain unverified. The
local regression test establishes override absence only.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]. Organization inheritance takes
effect when the removal of local overrides reaches the default branch. No package configuration or
data migration is required. If repository-specific forms are needed again, restore a reviewed local
set with the understanding that it replaces the inherited set.

## Known Limitations and Follow-Up

Verify the hosted chooser after the default branch receives the change, including form fields, blank
issues, and support/security navigation. See [Validation](#validation) for outstanding evidence.
