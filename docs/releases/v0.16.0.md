# Popo v0.16.0

Version 0.16.0 adds standalone Apple release identity reporting and streamlines native configuration
validation and regression suites. This minor release is dated 2026-11-05 and documented in released
form at the maintainer's request. Tagging and publication remain separate operations.

## Highlights

Use `popo apple-release-identity` to report the agreed version/build of one explicitly selected
native application target as text or JSON. Optionally compare an explicitly supplied tag. See the
[release identity guide] for policy and output contracts, and the [changelog] for complete scope.

## Change Scope

Add exact target/product and complete configuration-set selection, numeric string validation,
literal agreement before normalization, explicit tag-prefix comparison and value-redacted errors.
Reject ambiguous targets and additional, missing, unnamed, duplicate or repeated configurations.
Unrelated targets do not contribute identity. Reuse confined literal paths and Xcode configuration
resolution with Apple metadata checks without changing their selection rules.

Track version/build pairs together and avoid temporary intersection sets and redundant dictionary
validation. Preserve diagnostic order, literal agreement, normalization and read-only behavior.
Strengthen class-based policy, identity, CLI and installed-command suites with named cases, unique
mutations, exact diagnostics, explicit UTF-8 fixtures and unchanged-input assertions. Exercise both
report formats and entry points with wheel/sdist installations.

## Compatibility and Configuration

The new optional command justifies a minor bump from v0.15.0. It requires explicit `apple-release`
policy and remains outside `check-all`, checks and profiles. Existing native check defaults,
configuration and text/JSON schemas remain unchanged. Identity JSON has its own schema version.
Distribution versions continue to derive from Git tags through `setuptools-scm`.

### Breaking Changes

No intentional existing command, configuration or runtime removal is introduced. The new command
requires exact native selection and literal numeric agreement. Two-part versions gain `.0`; builds
become positive integers. Agreed leading zeroes remain accepted, so this is not strict SemVer
validation. Tags are compared only when explicitly supplied; no Git state is inferred.

### Deprecations

No new deprecation or support-window commitment is introduced. Internal modules remain
implementation details; consumers should adopt the public CLI.

## Support Boundary

Popo requires Python >=3.13,<3.15. The command is offline and read-only, with no Git, Xcode, signing
tools or credentials required. Consumer version/build fields are reported intentionally; unrelated
settings, paths and native errors are excluded from reports and failure diagnostics.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.
Validate fresh wheel and source distributions, Twine metadata and clean installations. Development
SCM versions do not establish the metadata produced by the eventual immutable v0.16.0 tag.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. This preparation creates no tag or hosted release and publishes no package. No data
migration is required. Adopt a reviewed immutable pin with explicit consumer policy; roll back by
restoring the prior verified dependency pin and matching policy.

## Known Limitations and Follow-Up

Identity comes from literal source settings, not a built or signed application. The command does not
resolve inheritance, xcconfig files or variables, inspect archives, validate schemes/test plans,
verify tag existence, approve evidence or publish releases. Consumer build/signing checks remain
necessary, as do deadlines and failure handling for callers. Do not replace evidence after failure.

Rebuild and validate the final committed/tagged tree, intended version and release record before
delivery. Local validation does not establish hosted Linux/Windows or Python 3.13 success.
