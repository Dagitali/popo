# Popo v0.3.2

Version 0.3.2, tagged on 2026-09-30 (UTC), corrects omitted release records on `hotfix/0.3.2` after
the existing `v0.3.1` tag. This patch release adds a retrospective 0.3.1 record and the dated
changelog sections needed to distinguish that release from this correction. The tag does not
establish hosted validation or publication. See the [changelog].

## Highlights

- Backfill the 0.3.1 release document and dated changelog entry.
- Add the 0.3.2 release record and index both versions in the release archive.
- Preserve the original 0.3.1 tag and explicitly describe its missing changelog entry.

## Change Scope

This release updates `CHANGELOG.md` and the [release archive] and adds `v0.3.1.md` and `v0.3.2.md`
under `docs/releases/`. The documentation-alignment changes already tagged in 0.3.1 move from
`Unreleased` to their historical section. The new 0.3.2 section describes only the release-record
correction; `Unreleased` remains available for subsequent work.

Package implementation, tests, dependencies, workflow permissions, routing, and publication behavior
are unchanged. This is a forward correction, not a replacement of the earlier tag.

## Compatibility and Configuration

No compatibility or configuration changes. CLI commands, flags, settings, output, and exit codes are
unchanged. No consumer migration is required.

## Support Boundary

No support-boundary changes. Existing runtime requirements and public-interface boundaries
remain in force. The release does not add maintenance or publication commitments.

## Validation

The annotated `v0.3.2` tag date is verified from local Git metadata and expressed in UTC. The
results and pending checks below preserve preparation-time or retrospective evidence; they do not
establish additional tagged-artifact, hosted, or publication outcomes.

Local validation on 2026-09-30 passed against the 0.3.2 working-tree candidate:

- `make release-changelog RELEASE_VERSION=v0.3.1` and the corresponding `v0.3.2` check found both
  dated entries in the corrected changelog.
- `make docs-markdown` passed local link and heading-anchor validation.
- `make check-release` with a fresh temporary `PYTHON_DIST_DIR` passed lint, formatting, strict
  typing, all 274 unit/integration tests, repository checks, wheel/source builds, `twine check`, and
  all 18 artifact/clean-install tests.
- `git diff --check` passed; release-document reference definitions are sorted and unique.

The first isolated build attempt could not download dependencies in the restricted environment. The
complete release gate passed on retry with network access. The built distributions have a
Git-derived development version, not final `0.3.2`; they do not establish eventual tag/version
agreement. This validation-results wording was added after the artifact run and rechecked with the
Markdown and changelog gates.

Local candidate results do not establish hosted platform success or publication. Historical 0.3.1
validation remains separate from this correction.

## Deployment and Rollback

No cloud deployment, consumer-data migration, or PyPI publication is introduced. Authorized tagging
triggers release validation; GitHub publication retains its separate manual opt-in and environment
safeguards. Follow the [release policy] and [release playbook].

Correct any remaining documentation defect in a subsequent reviewed change. Do not move an existing
tag; reverting these records would reintroduce the missing release history.
