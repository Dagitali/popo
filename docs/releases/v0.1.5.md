# Popo v0.1.5

Version 0.1.5, tagged on 2026-09-24, makes the root `README.md` the overview displayed on Popo's
GitHub repository homepage. See the [changelog] for the release entry.

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Removes `.github/README.md`, the automation notes that took precedence over the public overview.
- Keeps the existing root [README] as the project's introduction, setup, and usage guide.

## Change Scope

Changes are limited to removing the competing README and updating release documentation. GitHub's
[README selection rules] prioritize `.github`, then the repository root, then `docs`. Removing the
`.github` copy allows the root overview to be selected without changing its contents.

## Compatibility and Configuration

No CLI, consumer configuration, dependency, workflow, or release-gate changes. Links to the removed
`.github/README.md` should use the root [README] or the relevant maintained contributor guide
instead. The deletion does not remove workflow or action configuration.

## Support Boundary

Python support, dependency bounds, and read-only repository checks are unchanged. This fix affects
repository presentation, not package runtime behavior.

## Validation

The annotated `v0.1.5` tag and date are verified from repository history. The notes below preserve
the preparation-time validation record. Pending checks and candidate references describe that stage;
the tag alone does not establish subsequent validation or publication results.

The preparation checklist required the final candidate commit and completion of:

- `make release-changelog RELEASE_VERSION=v0.1.5`;
- `make docs-markdown` and `make check`;
- Distribution and hosted release gates required by the [release policy]; and
- A visual check that GitHub displays the root README after the deletion reaches the default branch.

Local link checks do not prove the hosted homepage has changed. No hosted display or publication
result is asserted in this preparation record.

## Deployment and Rollback

The homepage correction takes effect for the default branch when the deletion is merged there; it
does not require cloud deployment or package publication. Tagging and optional GitHub Release
publication remain separate operations governed by the [release policy].

The removed notes remain recoverable from Git history. Restoring them at `.github/README.md` would
restore the competing homepage selection; retain any future automation notes under a different
filename or documentation location. No consumer-data migration is required.

## Known Limitations and Follow-Up

- Historical branches and tags retain their own README layout.
- Confirm the candidate commit, release date, hosted homepage, and release validation before
  finalizing this record.

See the [release archive] for related version records.
