# Popo v0.2.2

Version 0.2.2 expands source documentation without changing executable behavior. It covers changes
since `v0.2.1`; see the [changelog].

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Document configuration attributes, layout detection, default derivation, and path resolution.
- Explain checker inputs, results, errors, and the limits of text-based parsing.
- Distinguish returned CLI check statuses from argparse exits, and clarify the small package API
  and installed-metadata version lookup.

## Change Scope

Docstrings are expanded in nine modules: the package root, configuration, CLI, shared support,
and the action, changelog, dependency, Markdown, and Python-policy checkers.

The documentation explains dependency-name normalization, comments and URL fragments, ignored
markers and extras in minimum-bound comparisons, and partial parsing results. It also describes
Markdown fence handling, duplicate anchors, source exclusions, directory links, and resolved-target
boundaries. Workflow version resolution and action pinning are explicitly described as text-based
checks rather than full YAML validation or remote authenticity checks.

Changelog documentation distinguishes heading/date validation from section content, chronology,
and publication checks. Automation discovery describes its path-matching limits. Package
documentation distinguishes the source-import fallback version from Git-derived build versions.
These are explanations of existing behavior, not new capabilities or fixes to parser limitations.

## Compatibility and Configuration

No consumer compatibility or configuration changes. CLI commands, arguments, output, exit codes,
configuration keys, and validation logic remain unchanged. Introspection and generated help based
on Python docstrings expose the expanded text; no migration is required.

## Support Boundary

No support-boundary or dependency changes. Python remains `>=3.13,<3.15`, and the runtime
dependency remains `packaging>=26.3,<27`. The checks retain their read-only behavior and existing
consumer-policy boundaries.

## Validation

Preparation baseline: commit `2956f3414da5d9a3710cfefcb32e7fcb652a7d7b`, plus the uncommitted
docstring and release-document edits. The final candidate commit and tag are not yet established.

Before adding these release documents, local validation on macOS with Python 3.14.6 confirmed:

- All nine modified source modules have identical syntax trees after removing docstrings.
- `make check` passes all 215 unit/integration tests, lint, formatting, strict typing, and
  repository self-checks.
- `git diff --check` passes.

Validate this release record with `make release-changelog RELEASE_VERSION=v0.2.2` and
`make docs-markdown`. Distribution and installation tests were not rerun for the docstring-only
edits; before tagging, run `make check-release` with a fresh `PYTHON_DIST_DIR` and record the final
candidate commit. Hosted CI and tagged release validation, including the wheel-version match,
remain required by the [release policy]. Prior working-tree results do not prove a later tag.

## Deployment and Rollback

No cloud deployment, data migration, or PyPI publication is introduced. Authorized tagging triggers
release validation; optional GitHub publication retains its manual opt-in and environment gates.

If a documentation correction is needed, update the affected docstring and issue a subsequent
release rather than moving an existing tag. Reverting this documentation loses explanatory detail
but does not reverse a runtime behavior change.

## Known Limitations and Follow-Up

- Documented parser limitations remain; this release does not implement full Markdown or YAML
  parsing, remote action verification, or broader configuration validation.
- Confirm the release date and final commit, complete artifact and hosted gates, and update this
  record and archive status from verified results before claiming release completion.
