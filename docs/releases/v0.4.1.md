# Popo v0.4.1

Version 0.4.1, tagged on 2026-10-04, that repairs the maintained release history for 0.4.0. The
intended tag is `v0.4.1`; this record does not establish tagging or publication. See the [changelog]
and the retrospective [0.4.0 record].

- [Highlights](#highlights)
- [Change Scope](#change-scope)
- [Compatibility and Configuration](#compatibility-and-configuration)
- [Support Boundary](#support-boundary)
- [Validation](#validation)
- [Deployment and Rollback](#deployment-and-rollback)
- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

- Backfill the missing 0.4.0 release document and archive entry.
- Move the already-tagged 0.4.0 changes into their dated changelog section.
- Preserve the original tag and distinguish retrospective evidence from release validation.

## Change Scope

Documentation changes add the retrospective 0.4.0 record and this planned 0.4.1 record, index both
versions in the release archive, and synchronize the changelog and README release-status guidance.
The 0.4.0 record covers the full self-reference and actionlint feature change set rather than only
its most recent commits.

The original 0.4.0 tagged tree remains unchanged. Source code, tests, dependencies, package
configuration, and hosted workflows are unchanged by this patch.

## Compatibility and Configuration

No compatibility or configuration changes. CLI commands, flags, accepted inputs, diagnostics, exit
codes, and consumer settings retain their 0.4.0 behavior. No migration is required.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`; actionlint remains a consumer-provided
external tool. The records introduce no new runtime or publication commitments.

## Validation

The complete 0.4.1 documentation candidate passed current-checkout validation on 2026-10-04:

- `make check`, including lint, formatting, strict typing, 326 unit/integration tests, and
  configured repository checks.
- `make docs-markdown` for local links and heading anchors.
- `make release-changelog RELEASE_VERSION=v0.4.0` for the corrected dated section.
- `make release-changelog RELEASE_VERSION=v0.4.1` for the candidate's dated section.
- `git diff --check`.

Artifact and clean-installation checks were not run for this documentation-only edit. Complete the
release gates in the [release policy] before release. These local results do not establish tagged
0.4.1 artifact, hosted cross-platform, or publication results, and do not validate the immutable
0.4.0 tagged artifacts. The validation wording was subsequently rechecked with the Markdown and
0.4.1 changelog gates.

## Deployment and Rollback

No deployment, data migration, or publication behavior changes. Tag-triggered validation and
optional publication retain existing safeguards; preparing this record does not authorize tagging or
publishing. Follow the [release playbook] for release preparation.

Correct documentation errors through reviewed follow-up work. Preserve existing tags rather than
moving them; reverting this patch affects documentation without changing runtime behavior.

## Known Limitations and Follow-Up

- The original 0.4.0 tag still lacks its dated changelog section and release document.
- Complete candidate artifact and clean-installation checks and verify the eventual tag's version
  before claiming release readiness.
- Verify hosted validation and publication independently of current-checkout results.
