## Change Scope

Backfill the 0.8.1 dated changelog entry and release record from the changes already contained in

## Compatibility and Configuration

No CLI, configuration, runtime-dependency or workflow changes are introduced relative to 0.8.1. No
consumer migration is required for this documentation repair. The stricter input validation
introduced in 0.8.1 is described in its [release record].

### Breaking Changes

### Deprecations

No deprecations are recorded for this release.

## Support Boundary

Python remains `>=3.13,<3.15`. Runtime dependencies, distribution formats and publication safeguards
are unchanged. Python 3.15 support is outside this release.

## Validation

Interpret these results using the [evidence boundaries].

The preparation checkout passed `make docs-markdown`, `make release-changelog` for both `v0.8.1` and
`v0.8.2`, and `make check-release` with a fresh `PYTHON_DIST_DIR` on macOS/Python 3.14.8: 601
unit/integration tests, 50 artifact/clean-install tests, lint, formatting, strict typing and
repository policies passed. Both wheel and sdist passed Twine validation; the same artifacts were
used for clean-install testing.

The built version was `0.8.2.dev0+g64070d2d3.d20261023`, not `0.8.2`. New untracked release records
must be committed before final artifact validation includes them. The existing 0.8.1 tag's missing
records remain a historical limitation; these checks cannot repair that tree. Python 3.13 runtime,
hosted cross-platform validation, eventual 0.8.2 tag-version matching and publication require
separate evidence.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]; Popo's [release policy] retains
its local gates and opt-in safeguards. Distribution versions derive from Git tags through
`setuptools-scm`. This record does not establish GitHub Release or PyPI publication.

No data migration or hosted settings change is required. Restore a previous verified immutable
consumer pin to roll back behavior changes; correct release records through reviewed follow-up
changes. Keep existing tags immutable.

## Known Limitations and Follow-Up

The 0.8.2 tag has not been created. Complete final committed-tree artifact validation and
tag-version matching before release closeout; record hosted validation and any authorized
publication separately.
