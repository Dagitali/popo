# Popo v0.13.0

Version 0.13.0 adds Tree-sitter-backed Swift syntax analysis and aligns Python/Swift validation
abstractions while correcting repository-policy edge cases. This minor release is dated 2026-10-29
and documented in released form at the maintainer's request. Tagging and publication remain separate
operations.

## Highlights

See the [changelog] for dated scope, [source and log checks] for source conventions, and [result and
boundary checks] for architecture policy. Swift source and boundary checks share concrete syntax
without requiring a Swift installation; Python retains native AST analysis.

## Change Scope

Integrate `tree-sitter>=0.26.0,<0.27` and `tree-sitter-swift>=0.7.4,<0.8` with matching minimum
constraints. Recognize same-line declarations and imports, retain Unicode source locations, mask
comments, strings and regex literals, and attach documentation to its actual declaration. Selective
imports no longer masquerade as declarations requiring documentation. Keep bounded callable
interpretation and lexical recovery for grammar errors.

Share declaration, signature, documentation and boundary contracts through structural protocols,
immutable observations and fact factories. Align helper names and NumPy/DocC result/exception
terminology while retaining native parameter rules, generator priority, explicit raises versus
throws/rethrows, import matching and ownership semantics. Centralize Python parsing and docstring
spans in `_python_syntax.py`; use `ParsedSwiftSource` for Swift's concrete-syntax view.

Stream source discovery and markup inspection; skip disabled-rule analysis and reuse immutable
observations. Cache automation YAML, actionlint reference resolution and boundary ownership within
one validation run, refreshing later runs. Share confined UTF-8 input/error orchestration and
canonical approval-date parsing; preserve diagnostic ordering, scoped environment precedence,
read-only checks and redaction. Hash committed blobs through buffer views without changing inventory
checksums or memory limits.

Correct malformed hosted required-check evidence, approval URL ports and parser-depth handling.
Require integer npm lockfile versions 2 or 3 and validate exact pins with build metadata. Correct
Markdown heading collisions, titled angle-wrapped links/images and invalid decoded paths, including
NULs, without aborting independent checks.

Consolidate class-based parameterized tests and isolated fixtures, strengthen ordered diagnostics,
read-once and input-preservation assertions, and cover parser non-execution, symlink confinement,
thresholds, version boundaries and aggregate continuation. Alphabetize functions and methods without
changing fixture dependencies. Complete NumPy-style docstrings, including propagated versus reported
errors, within the 79-character limit; condense and consistently categorize changelog history.

## Compatibility and Configuration

The expanded Swift analysis capability justifies a minor bump from v0.12.0. Existing public
commands, policy selection, profiles and text/JSON schemas remain in place. Distribution versions
continue to come from Git through setuptools-scm; no authored version constant or second version
source is added.

### Breaking Changes

No intentional public command, configuration-key, package-root export or supported-runtime removal
is introduced. Validation is stricter for malformed hosted evidence, invalid approval ports and
floating-point npm lockfile versions. Consumers relying on those inputs must correct them; use
integer lockfile versions 2 or 3 and valid evidence/approval values. Swift declaration discovery can
identify policy violations previously hidden on shared physical lines. The two Tree-sitter runtime
dependencies must be available for the target environment.

### Deprecations

No new deprecation or support-window commitment is introduced. Internal checker abstractions are not
a promised consumer API; adoption examples continue to use the public CLI.

## Support Boundary

Popo requires Python >=3.13,<3.15. Native checks remain offline and read-only and do not execute
consumer source, invoke a Swift compiler, run consumer tests or export Xcode bundles. Tree-sitter
recovery does not establish compiler validity or semantic isolation. Swift callable contracts remain
bounded; Python dynamic imports, runtime bindings and alias shadowing remain outside static checks.
NumPy and DocC retain their distinct grammar and evidence rules.

### Artifact Contracts

The distribution remains `popo`, with the `popo` console script and `python -m popo` entry point.
Validate fresh wheel and sdist builds and their clean installations, including the additional native
parser dependencies. Check-result JSON remains separate from inventory and hosted-audit evidence.
Final tagged-tree version agreement and hosted platform validation require separate evidence.

## Deployment and Rollback

Follow the [release policy] and [release operations] for separately authorized tagging and optional
publication. This preparation creates no tag or hosted release and publishes no packages. Existing
tags remain immutable.

No consumer data migration is required. Update the reviewed immutable dependency pin and install its
runtime dependencies, then validate positive and negative policy cases through local and CI entry
points. Roll back by restoring the prior verified dependency pin and matching consumer policy.

## Known Limitations and Follow-Up

Rebuild and validate the final committed/tagged tree before delivery. Local validation does not
prove hosted cross-platform success or publication. Retain native compiler, test and packaging
checks in consumer repositories; shared entry-point parity checks inspect declarations rather than
executing the declared commands.
