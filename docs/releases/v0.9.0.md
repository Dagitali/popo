# Popo v0.9.0

Version 0.9.0 adds language-neutral policy selection and shared local/CI guardrail contracts for
Python, Swift, CDK and other repositories. This text is prepared in released form for 2026-10-24;
tagging and publication remain pending.

## Highlights

See the [changelog] for this version's concise change list and the [guardrail guide] for adoption.

## Change Scope

Add standalone `popo.toml`, explicit offline check selection and named profiles. Repositories can
select language-neutral checks without adding Python package metadata; existing aggregate defaults
remain available. Add `explain` for selection provenance without running validators, and versioned
JSON output for native offline commands with ordered check identities and diagnostics.

Add opt-in `check-guardrail-parity` for an explicit Make target/profile, local pre-commit hook and
CI-step invocation contract. Profiles can inspect their own wiring without executing the declared
commands. Inspect recipes across non-recipe comments, accepting harmless separators while rejecting
extra commands that comments previously hid. Collect hook matches in one traversal.

Separate native check adapters and their shared registry from CLI parsing so selected checks run
directly without rebuilding or reparsing the parser. Preserve command defaults and diagnostic
contracts, including continued collection after per-domain configuration failures. Align autopep8
with Ruff's complex-slice spacing by ignoring `E203` while preserving autopep8's default ignores.

Expand independent default-text, explicit-text and JSON scenarios and installed wheel/sdist coverage
for matching, Make, hook and workflow cases. Share diagnostic oracles and recursive byte snapshots.
Separate Markdown target/discovery/containment, reference/image and syntax suites without removing
existing cases or detailed method documentation. Verify `explain` never calls validation.

## Compatibility and Configuration

Without explicit selection, `check-all` retains its baseline checks and configured opt-in domains.
An explicit nonempty `checks` array replaces that selection; `--profile NAME` selects a named
profile instead. Unknown, duplicate or empty selections fail. External actionlint, hosted auditing
and version-dependent release checks remain separate commands.

When present, standalone `popo.toml` takes precedence over `[tool.popo]` in `pyproject.toml` without
merging. Standalone settings use the file's top level; remove an obsolete standalone file before
expecting Python metadata's policy to apply. Python-specific validators still require their own
metadata inputs, and Popo still requires a supported Python interpreter in non-Python projects.

Text remains the default output. Native offline `--format json` uses schema version one; hosted
auditing retains its separate schema and external actionlint retains its streams and exact status.
Configuration and reported check failures return one; success returns zero. Invalid CLI arguments
retain argparse's status two. See the [configuration reference] for schemas and exception
boundaries.

### Breaking Changes

No command or configuration schema is removed. Consumers using only `[tool.popo]` need no required
migration; repositories with an existing `popo.toml` must review its new authoritative role.
Introducing that file intentionally changes the policy source. Make contracts with extra commands
hidden after comments now fail; remove the extra commands or correct the declared contract. Explicit
selection can omit configured checks, so review the chosen profile before replacing existing local
or CI guardrails.

### Deprecations

No deprecations are introduced in this release.

## Support Boundary

Python remains `>=3.13,<3.15`. Runtime dependencies, wheel/sdist formats, read-only checker behavior
and publication safeguards are unchanged. Python 3.15 support is outside this release. Swift and CDK
repositories gain reusable repository checks, not Swift toolchain or CDK infrastructure semantic
validation. Consumer-specific policy and intentional domain differences remain consumer-owned.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]; Popo's [release policy] retains
its local gates and opt-in safeguards. This documentation does not create a tag or publish a GitHub
Release or package. Keep existing tags immutable.

Adopt a verified immutable release pin and validate the selected profile alongside current checks.
No data migration is required. To roll back, restore the prior verified pin and local validators;
remove new command flags, guardrail/profile configuration and standalone policy files that the older
version does not understand. Restore `[tool.popo]` policy when removing standalone overrides.

## Known Limitations and Follow-Up

Parity establishes literal declared wiring, not arbitrary shell equivalence, actual execution or
hosted enforcement. Make includes, variable expansion, hook exclusions and stages, workflow
conditions, credentials and installed tool versions remain outside this check. `explain` describes
selection without validating domain inputs or tool availability.

Shared remote policy bundles, workspace aggregation, generalized exceptions, SARIF, toolchain
reconciliation and Swift/CDK semantic adapters remain future work. Complete committed-tree artifact
validation, tag-version matching and hosted checks before release closeout. Record publication
separately if authorized.
