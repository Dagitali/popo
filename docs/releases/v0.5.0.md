# Popo v0.5.0

Version 0.5.0, tagged on 2026-10-06 (UTC), adds opt-in GitHub settings auditing. The tag does not
establish hosted validation or publication. See the [changelog] for concise scope and the [hosted
audit guide] for configuration and limits. The record covers the complete hosted-audit feature
merged into `develop`, including its source, tests, Make target, consumer guidance, and release
records.

## Change Scope

The release adds a hosted checker, configuration loader, CLI dispatch, deterministic unit tests, and
`make hosted-audit` with optional `HOSTED_AUDIT_ARGS`. README and configuration guidance link
consumer setup and evidence boundaries. Release documentation records the release's scope.

Audited expectations cover configured security settings, labels, CODEOWNERS, branch protection, and
required check contexts. Ordinary repository checks retain their offline behavior; the hosted audit
is excluded from `check-all` and `make check`. The adapter uses GET requests and does not change
hosted settings. Runtime dependencies, package version derivation, and publication workflows retain
their existing configuration.

## Compatibility and Configuration

This is an additive command and optional `[tool.popo.hosted]` configuration. Existing consumers need
no migration. To adopt the audit, supply explicit repository expectations and authenticated `gh`
access to github.com as described in the [hosted audit guide].

The command accepts `--root` and `--format text|json`; text is the default. Reports go to standard
output. Exit zero means every finding is verified or excepted. Exit one indicates drift,
inaccessible evidence, expired exceptions, or invalid configuration; argument errors retain exit
two. JSON configuration failures contain an `error` field.

Exceptions require a scoped owner, reason, approver, approval URL, and quoted ISO expiry date. They
apply only to confirmed drift, never inaccessible evidence. Expiry is inclusive through the
specified UTC day; expired exceptions fail even when the underlying drift has been corrected.

## Support Boundary

Python remains `>=3.13,<3.15`. The new command requires consumer-provided authenticated GitHub CLI
access and network connectivity to github.com. Tests use fake API responses and subprocess mocks;
ordinary validation does not require GitHub credentials. Internal checker helpers and data models
are not a promised consumer API.

## Deployment and Rollback

Adoption is opt-in; no data migration or hosted settings change is required. See
[release operations] for shared tagging and publication rules.

Consumers can stop invoking the audit and remove its optional configuration through review. Correct
release defects through reviewed follow-up work and a new version; preserve existing tags.

## Known Limitations and Follow-Up

- Evidence URLs refer to mutable resources and do not establish enforcement against every actor.
- The audit does not verify check-source App identity, bypass actors, review counts, merge queue
  execution, caller runs, notification delivery, or approval authenticity.
- CODEOWNERS is checked on the default branch; inaccessible evidence cannot establish absence.
