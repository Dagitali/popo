# Popo v0.6.5

Version 0.6.5, released on 2026-10-08, adopts Dagitali's organization pull request template by
removing Popo's local override.

- [Highlights](#highlights)

- [Validation](#validation)

- [Known Limitations and Follow-Up](#known-limitations-and-follow-up)

## Highlights

See the [changelog] for this version's concise change list.

## Change Scope

The release removes `.github/pull_request_template.md`, updates the contributor reference to the
organization template, and documents inheritance in README. Contributor guidance retains Popo's
packaging checks, agent-instruction review, read-only validation, and consumer-independent policy
requirements alongside the organization template's generic checklist.

## Compatibility and Configuration

Pull request authors use the organization template alongside Popo's [contributor requirements].
Packaging changes still require `make test-distribution test-installation`.

CLI commands, flags, configuration, diagnostics, exit codes, runtime dependencies, and workflows are
unchanged. Package consumers require no migration.

## Support Boundary

No support-boundary changes. Python remains `>=3.13,<3.15`.

## Validation

Interpret these results using the [evidence boundaries].

The preparation checkout passed `make docs-markdown`, `make release-changelog
RELEASE_VERSION=v0.6.5`, `make check` (426 unit/integration tests, lint, formatting, strict typing,
and repository checks), and `git diff --check` on 2026-10-08.

Artifact and clean-installation checks were skipped because this scope changes contributor reporting
and documentation rather than package behavior or metadata. Tag-version matching, hosted
cross-platform checks, publication, and inherited PR-template injection remain unverified. Local
checks do not establish GitHub's displayed template behavior.

## Deployment and Rollback

Shared tagging and publication rules are in [release operations]. Template inheritance takes effect
when the local override removal reaches the default branch. No package configuration or data
migration is required. Restore a reviewed local template if project-specific injection is needed
again; doing so overrides the organization default.

## Known Limitations and Follow-Up

Verify inherited template injection for a new pull request after integration. See
[Validation](#validation) for outstanding evidence.
